# AI 助教设计草案（#79，未实现）

本文件只记录**可执行的设计与验收边界**，不表示 AI 助教已接入。当前 `/assistant` 仍是规划中的入口；
没有配置服务端时，工作台其余功能不受影响。

## 为什么不能只改前端

- 模型密钥不能进入静态前端或构建产物；页面部署在 GitHub Pages 这类静态托管上，没有服务端。
- 需要一个后端适配层负责：鉴权、限流、超时、取消、上游地址白名单、错误映射、费用控制。
- 知识记录、错题、批注是本地数据；发送前必须由用户明确触发并展示发送范围。

## 建议架构

```text
浏览器（静态站点）
  └── POST /ai/explain           （用户主动触发，携带最小上下文）
        └── 服务端适配层（独立部署，不在本仓库静态构建中）
              ├── 读取 AI_PROVIDER / AI_MODEL / AI_BASE_URL / AI_API_KEY（仅服务端环境变量）
              ├── 校验请求体（场景、题目 id、上下文字段、长度上限）
              ├── 限流（每会话/每 IP）与超时（如 20s）
              └── 转发到 OpenAI-compatible 接口（自建 / Ollama / 远端，按模型实测）
```

前端侧约定：

- `POST /ai/explain` 请求体：`{ scenario: 'derivative' | 'concept' | 'mistake', context: {...}, question: string }`。
- 上下文字段按场景白名单：导数实验只传函数、区间、观察点与差商；错题只传该题字段；不传整本错题或全部批注。
- 响应：`{ ok: true, text, model, usage? }` 或 `{ ok: false, error }`；错误码区分未配置、超时、限流、上游错误。
- 未配置时页面显示「未配置 AI 服务」，**不生成任何伪造回答**。
- 流式输出可选；无论流式与否都必须支持停止生成。

## 验收清单（对应 #79）

- [ ] 服务端配置提供商、模型与密钥；无配置时明确提示。
- [ ] 发送前展示发送范围与目标服务；未经触发不上传本地学习数据。
- [ ] 鉴权、限流、请求体大小、超时、取消、网络/上游错误与费用边界。
- [ ] 前后端契约与输入校验测试；真实服务手动验证与模拟测试分开标注；密钥不进日志与构建产物。
- [ ] 模型输出标注「待核验」，不当成数学证明；提供停止生成与错误反馈。
- [ ] 更新接口/部署/隐私/使用文档；静态站点未配置后端时其他功能正常。
