# 设计文档

状态：基础工程已提供知识导航与绘图示例；错题本、AI 助教仍未实现。完整开发规范见 [development.md](development.md)，接口约定见 [contracts.md](contracts.md)。

## 目标用户与场景

数学分析课程学生在同一工作台中查阅概念、探索函数图像，并对照条件与反例纠正理解偏差。

## 信息架构

```text
学习工作台
├── 知识导航（MVP）
│   ├── 极限
│   ├── 连续
│   └── 导数
├── 绘图计算（MVP）
│   ├── 函数与范围输入
│   ├── 图像与错误提示
│   └── 数学解释与适用边界
├── 错题本（MVP 基础版）
└── AI 助教（可选）
```

## 技术方案

- React + TypeScript + Vite；Ant Design 与 CSS Modules；React Router hash 路由。
- mathjs 白名单表达式在 Worker 内采样，ECharts 展示，KaTeX 渲染公式。
- Zod 统一数据契约；版本化 localStorage 保存绘图默认设置与本地错题记录。
- Vitest / Testing Library 单元与组件测试，Playwright 验证完整流程，GitHub Actions 自动检查。
- 初版无后端或账号系统；构建产物需 HTTP 服务访问，不支持 file:// 双击打开。
- 数学内容与界面逻辑分离，知识数据位于 `src/content/knowledge`；卡片结构以 `shared/contracts` 为准。
- 错题记录含 `title`、`topic`、`problem`、`mistakeReason`、`correction` 与时间戳，字段语义见 [模块接口契约](contracts.md#错题本存储)。

## 质量设计

- 输入校验：表达式解析失败、非法范围、定义域问题有明确提示。
- 数学正确性：审查定理条件、反例及数值误差；记录人工核验依据。
- 可用性：键盘可操作，图表提供文字说明，不仅靠颜色传递信息。
- 隐私：MVP 不采集学生个人信息；可选存储功能需支持清除与导出。
- 安全：禁止直接执行用户表达式，第三方依赖许可证需核对。

## 测试计划

1. 数学内容审查：定义、条件、例题、反例。
2. 单元测试：范围校验、定义域与表达式异常处理。
3. 集成测试：导航切换、函数输入、图表更新与错误反馈。
4. 人工验收：新用户依据 README 启动并完成示例流程。

依赖版本以锁文件为准，运行命令见 README。测试不代替数学人工核验；新增功能继续补充实际测试结果与截图。

## 首页重构方向

产品定位：面向学习数学分析的学生，将查概念、绘制函数和数列、示例练习与错题复习放在同一工作台；AI 助教仍是待开发入口。首页优先呈现可执行的学习任务，再使用绝对值函数展示一个真实反例，不以宣传文案和装饰性统计替代功能。保留原来的示例链接、数学说明和浏览器本地存储提示。

视觉约定：用冷灰白作为工作背景、深色文字与低饱和蓝强调操作；图中的橙色点仅用于标出不可导的位置。移动端导航采用可见的多行布局，保留所有入口及待开发状态的无障碍名称。页面需要兼容键盘、窄屏和减少动态效果。

方案调研：参考 [Impeccable](https://github.com/pbakaus/impeccable) 的 AI 界面审查与去模板化方法，以及 [Ant Design Pro](https://github.com/ant-design/ant-design-pro) 的 Ant Design 应用组织方式。前者采用 Apache-2.0、后者采用 MIT；本次只借鉴设计方法，没有复制其源代码或安装新的运行时依赖。继续使用项目现有 Ant Design、图标及已安装的 frontend-design skill，不引入另一套 UI 框架。首页与公共导航为第一阶段，其余功能页仍需按同一方向逐步审查和优化。
