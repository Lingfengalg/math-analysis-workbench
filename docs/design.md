# 设计文档

状态：初始设计提案，非已实现说明。

## 目标用户与场景

数学分析课程学生在同一工作台中查阅概念、探索函数图像，并对照条件与反例纠正理解偏差。

## 信息架构

```text
学习工作台
├── 知识导航（MVP）
│   ├── 极限
│   ├── 连续
│   └── 导数
├── 绘图计算（MVP）
│   ├── 函数与范围输入
│   ├── 图像与错误提示
│   └── 数学解释与适用边界
├── 错题本（可选）
└── AI 助教（可选）
```

## 技术方案待决策

- 在 Issue 中确定前端框架、数学表达式解析器、绘图库及测试工具。
- 优先评估无需后端即可使用的 MVP，并验证最终部署或离线使用方式。
- 数学内容与界面逻辑分离，便于审查、复用和独立贡献。
- 数据结构建议：知识卡片含 `id`、`topic`、`title`、`definition`、`conditions`、`examples`、`pitfalls`、`references`。

## 质量设计

- 输入校验：表达式解析失败、非法范围、定义域问题有明确提示。
- 数学正确性：审查定理条件、反例及数值误差；记录人工核验依据。
- 可用性：键盘可操作，图表提供文字说明，不仅靠颜色传递信息。
- 隐私：MVP 不采集学生个人信息；可选存储功能需支持清除与导出。
- 安全：禁止直接执行用户表达式，第三方依赖许可证需核对。

## 测试计划

1. 数学内容审查：定义、条件、例题、反例。
2. 单元测试：范围校验、定义域与表达式异常处理。
3. 集成测试：导航切换、函数输入、图表更新与错误反馈。
4. 人工验收：新用户依据 README 启动并完成示例流程。

实现后补充架构决策、依赖版本、实际运行命令、截图和测试结果。
